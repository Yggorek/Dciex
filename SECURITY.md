# Security Policy

## Supported Versions

Dciex is under active development. A formal policy defining supported versions has not been established, so support for specific releases cannot be guaranteed. When reporting an issue, include the affected version or commit if known.

## Reporting a Vulnerability

After the repository is public and GitHub Private Vulnerability Reporting is enabled, use the **Report a vulnerability** button under **Security → Advisories** to submit a private report.

Do not disclose vulnerability details in public Issues or Pull Requests. Do not use public issue forms to report security vulnerabilities.

## What to Include

Please include, when available:

- A brief description of the vulnerability
- Affected versions or commit
- Steps to reproduce
- Expected and actual behavior
- Potential impact
- A proof of concept

Do not include real secrets, passwords, or personal data in your report.

## Disclosure Process

The maintainer will review the report and may request additional information. The reporter and maintainer will coordinate on a fix and disclosure. Details of the vulnerability should remain private until disclosure has been agreed.
